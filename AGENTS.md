## Adonis/SQLite conventions
- Migrations: numbered `backend/database/migrations/N_name.ts` (1-12 used). New must be `13_...`+.
- **ENUMs** → TEXT + CHECK constraint on SQLite; unalterable (knex sqlite `alterColumn` rebuilds only via PRAGMA; raw `ALTER ... MODIFY` MySQL-only). Dialect-guard MariaDB-only raw SQL: `this.db.dialect.name === 'mysql'` (Schema classes; `this.db` = QueryClient/TransactionClient).
- **DECIMAL columns** stored as REAL (float64), come back as JS numbers — no `Number()` coercion (mysql2 returned strings; existing calls harmless no-ops).
- `trades.quantity`, `trades.filled_quantity`, `algo_positions.quantity` are DECIMAL(18,8) — fractional crypto quantities valid; never `Math.floor` fills. float64 can't hold exact 18,8 — same precision as before.
- **`rawQuery` results**: MySQL `[rows, fields]`; better-sqlite3 rows array (writes: `{ changes, lastInsertRowid }`). `const [rows] = ...` destructuring + `rows[0] || rows` MySQL-only — use `Array.isArray(res?.[0]) ? res[0] : res` (`KrakenFastEngine.isSqlite`, `TradingController.unwrap`). Writes: `res.affectedRows ?? res.changes`, `res.insertId ?? res.lastInsertRowid`.
- **Dialect detection**: `Database.connection().dialect.name` → `'better-sqlite3'` | `'mysql'` (`.dialectName` is `undefined`).
- JSON columns: mysql2 auto-parses; SQLite returns TEXT — every `table.json()` column MUST have `prepare`/`consume` JSON handlers in its model.
- Broker paths: IBKR (`@stoqey/ib`, socket-driven status), Kraken (REST, `syncOrderStatus` polling). Fast path Kraken-only: `KrakenFastEngine` + `KrakenWebSocketService` (WS prices + 100ms batched DB flush). `/api/fast/*` routes Kraken-only (no `broker` param). Kraken V1 WS: public ticker `wss://ws.kraken.com`, private `openOrders` `wss://ws-auth.kraken.com`, 15-min token from `/0/private/GetWebSocketsToken` (refreshed every 10 min). Orders via V0 REST `AddOrder` with `cl_ord_id` = clientOrderId UUID → WS `openOrders` updates map back by `cl_ord_id`. Kraken close updates status-only → `reconcileOne()` backfills fills from `QueryOrders`. Recovery query filters `broker='kraken' AND client_order_id IS NOT NULL` so slow-path Kraken trades (no cl_ord_id) aren't hijacked.
- **Intraminute fast-algo (2026-08-19)**: `FastAlgoService` is THE algo system (old 30-min `AlgoTradingService` + `/api/fast/*` controller deleted — merged in). 10s decision loop (configurable `fast_interval_seconds`, min 5), started in `start/jobs.ts` (web env). Gated by `algo_configs.fast_enabled` + `enabled` + `broker='kraken'`; idles otherwise (ticks, no API calls). Entries price-momentum (`MomentumFeed`: rolling 1s samples from Kraken WS cache; momentum over `fast_momentum_seconds` window + Wilder RSI-7 on 5s bins; gates `fast_momentum_threshold_pct` / `fast_rsi_low` / `fast_rsi_high`). Exits each tick vs live WS price: SL/TP (`fast_stop_loss_pct`/`fast_take_profit_pct`), momentum reversal (`fast_exit_reversal_pct`), force-close. Execution `KrakenFastEngine.placeOrder` (MARKET, direct REST, WS fills, 100ms DB flush) — NOT BullMQ slow path; lifecycle `algo_positions` (pending_entry → open → closing → closed) reconciled in-loop. Trade linking: engine flush assigns `tradeId` (poll `waitForTradeId` ≤3s); unlinked orders cancelled immediately. Portfolio via `KrakenService.getTradeBalance` cached 60s; engine auto-start 60s backoff; per-symbol cooldown `fast_cooldown_seconds`; daily-loss breaker shared with slow loop. `dryRun` logs only. Watchlist = `fast_watchlist` (JSON array, default BTC/ETH/SOL); symbols auto-subscribed to WS. Status `GET /api/algo/fast/status`; stats `GET /api/algo/stats` (getStats on `FastAlgoService`). Rate limits: loop in-memory (WS push), REST only on order placement → 10s cadence ≪ Kraken private limits.
- **Pure strategy core (2026-08-20)**: all entry/exit DECISIONS live in `FastStrategy` (`backend/app/services/FastStrategy.ts`) — deterministic, I/O-free, takes `(feed, symbol, price, now, cfg)` and returns signals + state to persist. `FastAlgoService` (live) and `BacktestEngine` (replay) both call it → live/backtest parity. Controls (migration `14_fast_strategy_controls`, all 0 = off): trailing stop (`fast_trailing_stop_pct` behind peak, armed after `fast_trailing_activate_pct` profit, peak tracked in `algo_positions.peak_price`), max-hold force-close (`fast_max_hold_seconds`), EMA trend filter (`fast_ema_period`; lenient while warming), volatility-adaptive SL/TP (`fast_volatility_window_seconds` + `fast_volatility_mult`; SL scales with per-minute vol, TP scales by the same factor keeping RR; `fast_volatility_floor_pct` avoids over-tight; `fast_volatility_ceiling_pct` skips wild entries). Exit priority: SL → TP → trailing → max-hold → reversal. `fastStrategyFromConfig(cfg)` maps an AlgoConfig-like object structurally (shared by service + command). NEVER put strategy math in the service — it must stay replayable.
- **Backtesting (2026-08-20)**: `BacktestEngine` (`backend/app/services/BacktestEngine.ts`) — pure event-driven replay of `{t, p}` samples through the SAME MomentumFeed + FastStrategy at the live decision cadence (`loopIntervalSeconds`). Cash accounting with per-side taker fee, cooldowns, max exposure; open positions force-closed at end (`end_of_test`). Metrics: win rate, PF, max drawdown, avg hold. `node ace backtest --symbol=BTC --hours=24` (ace command `backend/commands/backtest.ts`, needs `static options = { startApp: true }` — commands don't boot the app otherwise, models have no DB binding → "Cannot read properties of undefined (reading 'query')"). Data: Binance 1s klines public REST (`BinanceKlineService.fetchBinanceKlines1s`, no key, ~150ms/page, close-only samples), cached to `backend/backtests/cache/{SYM}_1s_{h}h.json` (load unless `--fresh`). Strategy config comes from the live `algo_configs` row. `BacktestEngine` feed is a class field — `run()` MUST call `feed.clearAll()` first (re-entrancy; unit tests reuse the instance).
- **Parameter sweep + calibration tooling (2026-08-20)**: `node ace backtest:sweep --symbol=BTC --hours=72` (`backend/commands/backtest_sweep.ts`) — one-at-a-time grid around the live config + 3 presets (scalp/trend/swing), ranked by PF (min-trades filter). `backtest` supports `--config '{"fastStopLossPct":0.8}'` (JSON overrides; LUCID MODEL FIELDS LIVE IN `$attributes` — never `{...modelInstance}`, use the explicit `pick()` in the command), `--end-hours-ago N` (walk-forward windows; cache keyed by window) and `--debug` (momentum percentiles per window — "why no trades?" diagnostics). First calibration verdict 2026-08-20: burst momentum (60s/0.15% gate = ~9%/hr bursts) sleeps through smooth +11-20% rallies; opening the RSI gate to catch them → WR ~20-30%, PF < 0.6 (chases trend peaks). Swing config (mom 120s, thr 0.3%, SL 1.2%, TP 3.0%, trail 0.5/0.8, EMA-40, cd 300s) had PF 1.57-3.92 but net only +0.18-1.37% — superseded by trend mode (below).
- **Trend-rider mode (2026-08-20, migration 15)**: `fast_trend_mode` replaces the momentum+RSI entry gate with a trend-confirmed entry: price above EMA (`fast_ema_period`; 1s samples, so 900 = 15min) + EMA slope ≥ `fast_trend_slope_pct` over `fast_trend_slope_window_seconds` (lenient while warming). No RSI overbought rejection (steady trends pin RSI at 100 — why burst mode sleeps through rallies). `fast_take_profit_pct` 0 = NO take profit — ride the trailing stop (`entryLevels` returns takeProfit=0, `evaluateExit` guards `pos.takeProfit > 0`; position rows store 0). Calibration 2026-08-20 (3 disjoint trending windows): EMA-900, slope 0.1%/1800s, SL 1.0%, trail 2.0/1.5, cooldown 1800s, reversal 1800s → net +3.46%/+2.21%/+2.54% (PF 3.3-3.5) vs swing's -0.44/+0.88/+1.37; -1.04% on flat chop (see regime gate below). `MomentumFeed.maxSamples` 2400→14400 (4h of 1s).
- **Regime + volume gates + intrabar fills + walk-forward (2026-08-20, migration 16)**: `fast_regime_ema_period`/`fast_regime_slope_window_seconds`/`fast_regime_slope_min_pct` (trend mode only, 0 = off) — stand aside unless a SLOW EMA (3600 = 1h) slope confirms the market is trending; halves the flat-market bleed (-1.04% → -0.53%/3d at 0.3% threshold) and improved ETH +3.46→+4.31% (29t vs 63t) but cost BTC36h +2.21→+1.15%. `fast_volume_window_seconds`/`fast_volume_min_ratio` — entry-bar volume vs rolling median; NO measurable effect on any window (1s volume too spiky, last-bar-vs-median rarely blocks) → shipped off; also skipped live (Kraken WS has no per-tick volume — backtest-only). Backtest engine now fills SL/TP **intrabar** at the level price (samples carry h/l/v from Binance; old close-only behavior = maxHigh/minLow over closes), trailing/reversal still at decision closes (conservative). `node ace backtest:walkforward --symbol=BTC --hours=72 --windows=3` — sweep window N, validate winner on N+1, PASS/FAIL verdicts; first run: ALL configs FAIL OOS (flat-window PF is noise — PF 3.32 in-sample → -1.47% OOS; only ~9 days of 1s data exist, one trending window at the end, so formal certification is data-limited). Binance fetcher: bounded 429/418 retries (5, exponential) — unbounded retry looped forever under rate limits. Cache files bumped `_v2` (h/l/v). 252 unit tests.
- **Functional suite 502s in this env (pre-existing 2026-08-20)**: every functional spec gets 502 from `testUtils.httpServer()` while `node ace serve` (dev or `NODE_ENV=test`) serves 200. Unrelated to strategy work; unit suite is the reliable gate (232 passing, incl. strategy + backtest specs).
- **`@stoqey/ib` 1.6.7 typing regression**: `IBApi.on()` types only 7 events (`all/connected/disconnected/info/error/server/received`), runtime emits every `EventName`. `IBKRService` reopens `on/once/off` via `IbConnection` intersection type — keep pattern for new events.

## Meilisearch quirks
- ≥1.13: **no create-index route** (POST/PUT `/indexes` → 405). Indexes implicit via settings PATCH; set primary key `PATCH /indexes/:uid` `{"primaryKey":"id"}` after — else docs with several `*Id` fields fail inference, writes silently rejected. `MeilisearchService.ensureIndex()` handles it; keep.
- Search `limit` caps at index `pagination.maxTotalHits` — batch fetches must stay under.
