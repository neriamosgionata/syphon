## Adonis/SQLite conventions
- Migrations: numbered `backend/database/migrations/N_name.ts` (1-12 used). New must be `13_...`+.
- **ENUMs** → TEXT + CHECK constraint on SQLite; unalterable (knex sqlite `alterColumn` rebuilds only via PRAGMA; raw `ALTER ... MODIFY` MySQL-only). Dialect-guard MariaDB-only raw SQL: `this.db.dialect.name === 'mysql'` (Schema classes; `this.db` = QueryClient/TransactionClient).
- **DECIMAL columns** stored as REAL (float64), come back as JS numbers — no `Number()` coercion (mysql2 returned strings; existing calls harmless no-ops).
- `trades.quantity`, `trades.filled_quantity`, `algo_positions.quantity` are DECIMAL(18,8) — fractional crypto quantities valid; never `Math.floor` fills. float64 can't hold exact 18,8 — same precision as before.
- **`rawQuery` results**: MySQL `[rows, fields]`; better-sqlite3 rows array (writes: `{ changes, lastInsertRowid }`). `const [rows] = ...` destructuring + `rows[0] || rows` MySQL-only — use `Array.isArray(res?.[0]) ? res[0] : res` (`KrakenFastEngine.isSqlite`, `TradingController.unwrap`). Writes: `res.affectedRows ?? res.changes`, `res.insertId ?? res.lastInsertRowid`.
- **Dialect detection**: `Database.connection().dialect.name` → `'better-sqlite3'` | `'mysql'` (`.dialectName` is `undefined`).
- JSON columns: mysql2 auto-parses; SQLite returns TEXT — every `table.json()` column MUST have `prepare`/`consume` JSON handlers in its model.
- Broker paths: IBKR (`@stoqey/ib`, socket-driven status), Kraken (REST, `syncOrderStatus` polling). Fast path Kraken-only: `KrakenFastEngine` + `KrakenWebSocketService` (WS prices + 100ms batched DB flush). `/api/fast/*` routes Kraken-only (no `broker` param). Kraken V1 WS: public ticker `wss://ws.kraken.com`, private `openOrders` `wss://ws-auth.kraken.com`, 15-min token from `/0/private/GetWebSocketsToken` (refreshed every 10 min). Orders via V0 REST `AddOrder` with `cl_ord_id` = clientOrderId UUID → WS `openOrders` updates map back by `cl_ord_id`. Kraken close updates status-only → `reconcileOne()` backfills fills from `QueryOrders`. Recovery query filters `broker='kraken' AND client_order_id IS NOT NULL` so slow-path Kraken trades (no cl_ord_id) aren't hijacked.
- **Intraminute fast-algo (2026-08-19)**: `FastAlgoService` is THE algo system (old 30-min `AlgoTradingService` + `/api/fast/*` controller deleted — merged in). 10s decision loop (configurable `fast_interval_seconds`, min 5), started in `start/jobs.ts` (web env). Gated by `algo_configs.fast_enabled` + `enabled` + `broker='kraken'`; idles otherwise (ticks, no API calls). Entries price-momentum (`MomentumFeed`: rolling 1s samples from Kraken WS cache; momentum over `fast_momentum_seconds` window + Wilder RSI-7 on 5s bins; gates `fast_momentum_threshold_pct` / `fast_rsi_low` / `fast_rsi_high`). Exits each tick vs live WS price: SL/TP (`fast_stop_loss_pct`/`fast_take_profit_pct`), momentum reversal (`fast_exit_reversal_pct`), force-close. Execution `KrakenFastEngine.placeOrder` (MARKET, direct REST, WS fills, 100ms DB flush) — NOT BullMQ slow path; lifecycle `algo_positions` (pending_entry → open → closing → closed) reconciled in-loop. Trade linking: engine flush assigns `tradeId` (poll `waitForTradeId` ≤3s); unlinked orders cancelled immediately. Portfolio via `KrakenService.getTradeBalance` cached 60s; engine auto-start 60s backoff; per-symbol cooldown `fast_cooldown_seconds`; daily-loss breaker shared with slow loop. `dryRun` logs only. Watchlist = `fast_watchlist` (JSON array, default BTC/ETH/SOL); symbols auto-subscribed to WS. Status `GET /api/algo/fast/status`; stats `GET /api/algo/stats` (getStats on `FastAlgoService`). Rate limits: loop in-memory (WS push), REST only on order placement → 10s cadence ≪ Kraken private limits.
- **Pure strategy core (2026-08-20)**: all entry/exit DECISIONS live in `FastStrategy` (`backend/app/services/FastStrategy.ts`) — deterministic, I/O-free, takes `(feed, symbol, price, now, cfg)` and returns signals + state to persist. `FastAlgoService` (live) and `BacktestEngine` (replay) both call it → live/backtest parity. Controls (migration `14_fast_strategy_controls`, all 0 = off): trailing stop (`fast_trailing_stop_pct` behind peak, armed after `fast_trailing_activate_pct` profit, peak tracked in `algo_positions.peak_price`), max-hold force-close (`fast_max_hold_seconds`), EMA trend filter (`fast_ema_period`; lenient while warming), volatility-adaptive SL/TP (`fast_volatility_window_seconds` + `fast_volatility_mult`; SL scales with per-minute vol, TP scales by the same factor keeping RR; `fast_volatility_floor_pct` avoids over-tight; `fast_volatility_ceiling_pct` skips wild entries). Exit priority: SL → TP → trailing → max-hold → reversal. `fastStrategyFromConfig(cfg)` maps an AlgoConfig-like object structurally (shared by service + command). ## Meilisearch quirks
- ≥1.13: **no create-index route** (POST/PUT `/indexes` → 405). Indexes implicit via settings PATCH; set primary key `PATCH /indexes/:uid` `{"primaryKey":"id"}` after — else docs with several `*Id` fields fail inference, writes silently rejected. `MeilisearchService.ensureIndex()` handles it; keep.
- Search `limit` caps at index `pagination.maxTotalHits` — batch fetches must stay under.
