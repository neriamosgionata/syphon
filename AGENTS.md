# Adonis Backend Instructions

## Environment quirks
- **`NODE_OPTIONS` hook-shim — FIXED globally (2026-08-10)**: headroom's opencode plugin used to inject `NODE_OPTIONS=--import=file://.../hook-shim/handler.js` pointing at a file missing from the installed wheel, so every `node`/`npx` failed with `ERR_MODULE_NOT_FOUND`. Root cause fixed: shim restored at `~/.local/share/uv/tools/headroom-ai/lib/python3.13/site-packages/headroom/providers/opencode/hook-shim/handler.js` (+ `installHeadroomTransport` added to the bundle's exports). `unset NODE_OPTIONS` is no longer needed. Safety net: `~/.config/node-options-guard.sh` (sourced in `.bashrc`, exported as `BASH_ENV`) strips dead `--import=` flags if the file ever disappears again (e.g. after a headroom upgrade). If `ERR_MODULE_NOT_FOUND` on that shim reappears, re-check the shim file + guard.
- **Do NOT typecheck with plain `tsc`**: Adonis IOC aliases (`App/*`, `@ioc:*`) only resolve through the Adonis assembler. Plain `tsc --noEmit` floods with TS2307 noise. Use `node ace build --production` (compiles to `backend/build/`) — it fails on real type errors. (Note: in this repo the workspace-hoisted deps break `adonis-preset-ts`'s relative `baseUrl`, so `ace build` also floods TS2307; app still boots and runs fine via the runtime IOC.)
- **Tests**: `cd backend && npm test` runs the unit suite and the functional suite as **separate processes** (`bootstrap.ts unit && bootstrap.ts functional`). Suite names are positional args (japa has no `--suite` flag; `--groups` filters test *group titles*, `--files` does suffix matching — neither selects a suite). Requires: Redis (6379), Meilisearch (7700) running + `backend/.env` (copy `.env.example`; none exists — create from README). DB is SQLite (`backend/syphon.sqlite3`, created by `node ace migration:run` — no external DB needed). The suites must stay in separate processes: unit specs boot a throwaway Application with stub IoC bindings, and any app service imported there (e.g. `MeilisearchService`) gets cached in the module graph with stub Env/Redis values — the functional app in the same process would reuse those poisoned singletons (401s). Unit specs restore the global `ioc.use/make/call` hooks in teardown (see `tests/unit/helpers/ioc-hooks.ts`) and their Env stubs mirror real MEILI_* values for the same reason.
- **Infra**: Redis is a docker container on 6379 (native `redis-server.service` is disabled — the container can't bind while it's running). Redis + Meili via `docker compose up -d redis meilisearch` (podman, rootless). Meili is memory-limited in `docker-compose.yml` (512M + `MEILI_MAX_INDEXING_MEMORY`); a 128M limit made it OOM-loop (100s of restarts) and every API call from the tests failed with `fetch failed` — `podman restart syphon-meilisearch` if that happens again.
- `npm install` requires `--legacy-peer-deps`.

## Adonis/SQLite conventions
- Migrations: numbered files `backend/database/migrations/N_name.ts` (1-12 used). New migration must be `13_...`+.
- **ENUMs** become TEXT + CHECK constraint on SQLite — they cannot be altered (knex sqlite `alterColumn` only rebuilds via PRAGMA, raw `ALTER ... MODIFY` is MySQL-only). Dialect-guard MariaDB-only raw SQL with `this.db.dialect.name === 'mysql'` (works in Schema classes; `this.db` is the QueryClient/TransactionClient there).
- **DECIMAL columns** are stored as REAL (float64) on SQLite and come back as JS numbers — no `Number()` coercion needed (mysql2 returned strings; existing `Number()` calls are harmless no-ops).
- `trades.quantity`, `trades.filled_quantity`, `algo_positions.quantity` are DECIMAL(18,8) — crypto fractional quantities are valid; never `Math.floor` fills. Note float64 cannot hold exact 18,8 — same precision profile as before (values were Number()-coerced strings).
- **MySQL `rawQuery` returns `[rows, fields]`; better-sqlite3 returns the rows array** (or `{ changes, lastInsertRowid }` for writes). `const [rows] = await rawQuery(...)` destructuring and `rows[0] || rows` idioms are MySQL-only — use `Array.isArray(res?.[0]) ? res[0] : res` style unwraps (`FastTradeEngine.isSqlite`, `TradingController.unwrap`). Write results: use `res.affectedRows ?? res.changes` and `res.insertId ?? res.lastInsertRowid`.
- **Dialect detection**: `Database.connection()` returns a QueryClient whose `.dialectName` is `undefined`. Use `Database.connection().dialect.name` — `'better-sqlite3'` or `'mysql'` (see `FastTradeEngine.isSqlite`, `MetricsController.getDatabaseMetrics`).
- JSON columns: mysql2 auto-parsed JSON; SQLite returns TEXT — every `table.json()` column MUST have `prepare`/`consume` JSON handlers in its model.
- Broker paths: IBKR (`@stoqey/ib`, socket-driven status), Kraken/Binance (REST, `syncOrderStatus` polling), FastTradeEngine (Binance WS + 100ms batched DB flush).
- SQLite runs with WAL, `synchronous=NORMAL`, `busy_timeout=5000`, `foreign_keys=ON` (set in `config/database.ts` pool.afterCreate).

## Meilisearch quirks
- Modern Meilisearch (≥1.13) has **no create-index route** (POST/PUT `/indexes` → 405). Indexes are created implicitly by a settings PATCH; set the primary key via `PATCH /indexes/:uid` `{"primaryKey":"id"}` afterwards — otherwise documents with several `*Id` fields fail primary-key inference and every write is silently rejected. `MeilisearchService.ensureIndex()` handles this; keep it that way.
- Search `limit` caps at the index `pagination.maxTotalHits` setting — batch fetches must stay under it.

## Workflow
- After editing backend code: run `unset NODE_OPTIONS && cd backend && npm test` (or `npm run test:unit` / `npm run test:functional`).
- After editing frontend: `cd frontend && npm test`.
